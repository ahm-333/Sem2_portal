1. ما هي شجرة البحث الثنائية (Binary Search Tree)؟

يا شباب، بعد ما فهمنا في المحاضرة السابعة إزاي الـ Binary Tree العادية بتشتغل، واكتشفنا إن أي عقدة مسموح لها بطفلين كحد أقصى (Left & Right)، بيظهر عندنا سؤال محوري: هل شجرة ثنائية عشوائية بتساعدنا في البحث السريع؟

الإجابة الصادمة: لأ طبعاً! لو الشجرة مترتبة عشوائياً، وعايزين ندور على رقم، هنضطر نزور كل العقد عقدة عقدة وده بياخد وقت O(n) بالظبط زي الـ Unsorted Array أو الـ Linked List!

من هنا ابتكر علماء الحاسب فكرة عبقرية اسمها شجرة البحث الثنائية (BST). الفكرة ببساطة إننا بنفرض قانون ترتيب صارم (Ordering Property) بيخلّينا نكمّل البحث في فرع واحد بس بعد كل مقارنة.

التعريف الأكاديمي الرسمي من السلايد (Slide 8):

"A Binary Search Tree is a node-based binary tree data structure with the following key properties:
1. Binary Tree Structure: Each node has at most two children.
2. Ordering Property: For any given node:
• All values in its left subtree are LESS than the node's value.
• All values in its right subtree are GREATER than the node's value."

ترتيب حقول العقدة في الذاكرة على نظام بمؤشرات 8 بايت
عنوان العقدة في الـ Heap: 0x7ffee0a0 (حجم شائع: 24 bytes)
البيانات data (50) 4 bytes + 4 padding
مؤشر اليسار left 8 bytes
مؤشر اليمين right 8 bytes
💡 قاعدة الذهب في الـ BST: أي قيمة تشاور عليها left لازم تكون أصغر من 50، وأي قيمة يشاور عليها right لازم تكون أكبر من 50 قطعيًا!

تفكيك كود تعريف العقدة في C++:

struct Node {
  int data;         // القيمة المخزنة داخل العقدة
  Node* left;       // مؤشر يشاور على الابن الأيسر (أصغر)
  Node* right;      // مؤشر يشاور على الابن الأيمن (أكبر)

  Node(int val) : data(val), left(nullptr), right(nullptr) {}
};
  • left(nullptr) و right(nullptr): أول ما العقدة بتتولد في الـ Heap، بتكون ورقة معزولة (Leaf) مش بتشاور على أي أبناء لحد ما نربطها.
  • شرط التفرد (Uniqueness): معظم تطبيقات الـ BST الأكاديمية بتفترض عدم تكرار الأرقام (Unique Keys). لو احتجنا تكرار، بيتفق المحاضر إما نخزن المكرر في اليسار دائماً أو في اليمين دائماً.

2. بناء شجرة BST خطوة بخطوة (Slide 9 & 10)

تعالوا نطبق مثال السلايد رقم 9 بالحرف: "Let's build a BST by inserting the numbers: 50, 30, 70, 20, 40, 60, 80".

القاعدة الذهبية للإدخال (Insert Rule):
1. بنبدأ نقارن الرقم الجديد مع الـ Root.
2. لو الرقم الجديد أصغر من العقدة الحالية ← نتحرك شمال.
3. لو الرقم الجديد أكبر من العقدة الحالية ← نتحرك يمين.
4. نكرر المقارنة لحد ما نوصل لمؤشر فاضي (nullptr)، نزرع العقدة الجديدة هناك كورقة (Leaf Node).

الشكل النهائي بعد إدخال 50, 30, 70, 20, 40, 60, 80

• الشجرة الفرعية اليسرى للـ 50 كاملة (30, 20, 40) جميع قيمها أصغر من 50.

• الشجرة الفرعية اليمنى للـ 50 كاملة (70, 60, 80) جميع قيمها أكبر من 50.

• الخاصية دي متحققة تكرارياً (Recursively) عند كل عقدة! العقدة 30 يسارها 20 ويمينها 40.

3. خوارزمية البحث في الـ BST والتعقيد الزمني (Slide 14)

في كل مقارنة، لو القيمة مش موجودة عند العقدة الحالية بنكمّل في فرع واحد ونستبعد الفرع التاني كله. عدد العقد اللي بنستبعدها بيتغيّر حسب شكل الشجرة.

لو إنت واقف عند عقدة قيمتها 50 وبتدور على 20، بمجرد ما تقارن وتلاقي 20 < 50، إنت متأكد 100% إن الرقم مستحيل يكون موجود في أي مكان على يمين الـ 50، فبتهمل الشجرة اليمنى بالكامل!

كود دالة البحث التكرارية (Recursive Search):

Node* search(Node* root, int key) {
  // الحالة الأولى: وصلنا لنهاية الشجرة بدون ما نلاقيه، أو لقيناه في الـ root
  if (root == nullptr || root->data == key)
    return root;

  // الحالة الثانية: الرقم المطلوب أصغر من العقدة الحالية ← ابحث في اليسار
  if (key < root->data)
    return search(root->left, key);

  // الحالة الثالثة: الرقم المطلوب أكبر من العقدة الحالية ← ابحث في اليمين
  return search(root->right, key);
}

مقارنة التعقيد الزمني (Time Complexity):

الحالة التعقيد الزمني التفسير الأكاديمي
المطابقة عند الجذر O(1) بنلاقي القيمة بأول مقارنة.
أسوأ حالة لارتفاع معيّن O(h) بنتتبّع مسار واحد. لو الارتفاع محسوب بالحواف، المسار فيه بحد أقصى h + 1 عقدة.
شجرة متزنة O(log n) الارتفاع بيكبر لوغاريتميًا مع عدد العقد.
شجرة مائلة بالكامل O(n) إدخال 10, 20, 30, 40 بالترتيب يعمل سلسلة من n عقد وارتفاعها n − 1 حافة.

4. عملية الحذف (Deletion) والحالات الثلاث المعقدة (Slide 13)

الحذف في الـ BST هو أصعب وأهم موضوع بيسألوا فيه في الامتحانات والـ Interviews، لأن حذف عقدة ممكن يكسر توازن وروابط الشجرة كلها لو معملناهوش بحرفية.

عندنا 3 سيناريوهات واضحة للحذف:

الحالة الأولى: العقدة ورقة ملهاش أبناء (No Children - Leaf Node)

أسهل حالة: العقدة مش مرتبطة بأي أولاد تحتها (left == nullptr && right == nullptr).

طريقة الحل: بنمسح العقدة من الذاكرة بـ delete ونخلي المؤشر اللي في الأب بتاعها يشاور على nullptr وخلاص!

الحالة الثانية: العقدة لها ابن واحد فقط (One Child)

العقدة عندها ابن واحد إما في اليمين أو في الشمال.

طريقة الحل (التجاوز - Bypass): زي الحذف في الـ Linked List بالظبط، بنخلي الأب بتاع العقدة يشاور مباشرة على حفيدها (ابن العقدة المراد حذفها)، وبعدين نمسح العقدة من الذاكرة.

الحالة الثالثة (الملكية): العقدة لها طفلان (Two Children)

دي الحالة اللي محتاجة تركيز عالي! العقدة عندها فرع يسار وفرع يمين، مين اللي يقعد على عرشها بعد ما نحذفها من غير ما يكسر قانون الـ BST؟

عندنا حلين عبقريين:

1. الخليفة في الترتيب (Inorder Successor): أصغر قيمة في الشجرة الفرعية اليمنى (أول عقدة على أقصى يسار الفرع الأيمن).

2. السلف في الترتيب (Inorder Predecessor): أكبر قيمة في الشجرة الفرعية اليسرى (أول عقدة على أقصى يمين الفرع الأيسر).

خطوات التنفيذ البرمجية:
• بنجيب قيمة الـ Inorder Successor وننسخ قيمته في العقدة المراد حذفها.
• بنستدعي دالة الحذف تكرارياً (Recursively) لحذف الـ Successor من مكانه القديم (وده هيكون إما Leaf أو عنده ابن واحد، فيتحذف بمنتهى السهولة).

كود C++ المعتمد لعملية الحذف:

Node* findMin(Node* root) {
  while (root->left != nullptr) root = root->left;
  return root;
}

Node* deleteNode(Node* root, int key) {
  if (root == nullptr) return root;

  if (key < root->data) {
    root->left = deleteNode(root->left, key);
  } else if (key > root->data) {
    root->right = deleteNode(root->right, key);
  } else {
    // لقيت العقدة المراد حذفها!
    // حالة 1 أو 2: ابن واحد أو بدون أبناء
    if (root->left == nullptr) {
      Node* temp = root->right;
      delete root;
      return temp;
    } else if (root->right == nullptr) {
      Node* temp = root->left;
      delete root;
      return temp;
    }

    // حالة 3: العقدة لها طفلان
    Node* temp = findMin(root->right); // Inorder Successor
    root->data = temp->data;           // انسخ القيمة
    root->right = deleteNode(root->right, temp->data); // احذف السكسيسور
  }
  return root;
}

6. هيكل بيانات الرسم البياني (Graph Data Structure)

وصلنا دلوقتي للجزء الثاني في المحاضرة الثامنة: الـ Graphs. الـ Graph هو أعم وأشمل هيكل بيانات غير خطي في علوم الحاسب. كل شبكات التواصل الاجتماعي (Facebook, LinkedIn)، خرائط جوجل (Google Maps)، وشبكات الإنترنت هي في حقيقتها Graphs عملاقة!

الرسم البياني رياضياً وبرمجياً يُعرّف بزوج: G = (V, E):
• V (Vertices / Nodes): مجموعة الرؤوس أو العقد (زي الأشخاص أو المدن).
• E (Edges / Arcs): مجموعة الحواف أو الروابط اللي بتوصل بين الرؤوس.

الشجرة (Tree)

الشجرة هي حالة خاصة جداً من الجراف! A Tree is a connected, undirected graph with NO cycles. عدد حواف الشجرة دائماً |E| = |V| - 1، وفيه مسار واحد وحيد بين أي نقطتين.

الجراف العام (General Graph)

يقدر يحتوي على دورات (Cycles)، مسارات متعددة، أو حتى عقد منفصلة (Disconnected Components). مفيش مفهوم Root إجباري، ومفيش اتجاه هرمي مفروض.

أنواع الحواف والجرافات (من السلايدات الرسمية):

  • 1. حواف موجهة (Directed Edges): الرابط له اتجاه سهمي صريح من u إلى v. بنكتبها كزوج مرتب ⟨u, v⟩ ≠ ⟨v, u⟩. زي الـ Follow في تويتر (تقدر تعمل فولو لحد من غير ما هو يعملك فولو).
  • 2. حواف غير موجهة (Undirected Edges): الرابط متبادل وطريق رايح جاي. بنكتبها كمجموعة {u, v} = {v, u}. زي الصداقة في فيسبوك (علاقة ثنائية).
  • 3. الجراف الكامل (Complete Graph): في الجراف الكامل البسيط كل عقدتين مختلفتين بينهم حافة، وفي النوع الموجّه فيه سهم في كل اتجاه.
    • في الجراف غير الموجه، عدد الحواف الكلي: m = n(n − 1) / 2.
    • في الجراف الموجه، عدد الحواف الكلي: m = n(n − 1).
  • 4. درجة العقدة (Degree): عدد الروابط المتصلة بالعقدة. في الموجه، بتتقسم لـ In-degree (عدد الأسهم الداخلة) و Out-degree (عدد الأسهم الخارجة).

7. طرق تمثيل الرسوم البيانية برمجياً (Slide 294 & 484)

إزاي الكمبيوتر بيخزن شبكة علاقات معقدة في الذاكرة؟ السلايدات بتركّز على طريقتين هما الأساس في كل لغات البرمجة:

الطريقة الأولى: مصفوفة التجاور (Adjacency Matrix - 2D Array)

بنحجز مصفوفة ثنائية الأبعاد حجمها V × V. لو فيه رابط بين العقدة i والعقدة j بنحط 1 (أو وزن الرابط Weight)، ولو مفيش رابط بنحط 0. 

// Order: A, B, C, D, E
int adj[5][5] = {
    {0, 1, 1, 0, 0}, // A
    {1, 0, 0, 1, 0}, // B
    {1, 0, 0, 1, 0}, // C
    {0, 1, 1, 0, 1}, // D
    {0, 0, 0, 1, 0}  // E
};
  • الميزة الجبارة: فحص وجود رابط بين أي نقطتين سريع جداً O(1).
  • العيب القاتل: بتستهلك ذاكرة ضخمة O(V²) حتى لو الجراف مفيهوش غير حواف قليلة جداً (Sparse Graph).

الطريقة الثانية: قوائم التجاور (Adjacency List - Linked Lists)

بدل حجز مصفوفة مربعة مهدرة، بنعمل مصفوفة حجمها V فقط، وكل خانة بتحتوي على رأس قائمة متصلة (Linked List أو vector) بتسجل فقط الجيران الحقيقيين للعقدة! 

// A=0, B=1, C=2, D=3, E=4
vector<int> adjList[5] = {
    {1, 2},    // A: B, C
    {0, 3},    // B: A, D
    {0, 3},    // C: A, D
    {1, 2, 4}, // D: B, C, E
    {3}        // E: D
};
  • الميزة الجبارة: كفاءة مثالية في استهلاك الذاكرة O(V + E)؛ بنخزن الحواف الموجودة فعلياً بس.
  • المفاضلة: لو الجراف كثيف (Dense Graph) وروابطه كتير جداً، الـ Matrix بتكون أفضل. لو الجراف خفيف (Sparse Graph) وده أغلب الواقع، الـ List تتفوق باكتساح!

8. خوارزميات مسح الجراف: BFS و DFS بالتفصيل والتتبع

إزاي نزور كل عقد الجراف اللي ممكن نوصل لها من نقطة البداية بدون ما نلف في حلقات مفرغة (Infinite Loops) لو فيه دورات (Cycles)؟ الحل السحري: مصفوفة الزيارة (Visited Array / boolean array)؛ أي عقدة نزورها بنعلم عليها بـ true!

1. خوارزمية البحث في العرض (Breadth First Search - BFS)

السلاح السري: بتستخدم طابور Queue (FIFO).

الفكرة: استكشاف الجراف مستوى بمستوى (Level by Level)، زي موجة مياه بتنتشر من المركز للخارج. بنزور كل الجيران المباشرين الأول، بعدين جيران الجيران.
💡 سؤال امتحانات مضمون: الـ BFS تضمن إيجاد أقصر مسار (Shortest Path) في الجرافات غير الموزونة (Unweighted Graphs)!

بنبدأ من A ونفحص الجيران بترتيب القوائم اللي فوق. بنعلّم العقدة بمجرد ما تدخل الطابور.

ترتيب الزيارة A → B → C → D → E

الطابور بعد كل زيارة [B, C] → [C, D] → [D] → [E] → []

2. خوارزمية البحث في العمق (Depth First Search - DFS)

السلاح السري: بتستخدم مكدس Stack (LIFO) أو الاستدعاء الذاتي Recursion.

الفكرة: بتغوص في أقصى عمق للمسار لحد ما توصل لطريق مسدود، وبعدين ترجع لورا خطوة خطوة (Backtracking) وتجرب مسار تاني.

بنبدأ من A ونمشي على أول جار لسه ما اتزارش. عند C كل الجيران اتزاروا، فبنرجع لـ D ونكمّل لـ E.

ترتيب الزيارة A → B → D → C → E

Complete C++ Implementation (BST + Graph BFS/DFS)

المثال بيستخدم unique_ptr عشان كل عقدة تملك أبناءها والذاكرة تتحرر تلقائيًا. ترتيب الجيران هو ترتيب إضافة الحواف.

#include <iostream>
#include <memory>
#include <queue>
#include <string>
#include <vector>
using namespace std;

struct BSTNode {
    int data;
    unique_ptr<BSTNode> left;
    unique_ptr<BSTNode> right;

    explicit BSTNode(int value) : data(value) {}
};

class BST {
    unique_ptr<BSTNode> root;

    static void insert(unique_ptr<BSTNode>& node, int value) {
        if (!node) {
            node = make_unique<BSTNode>(value);
        } else if (value < node->data) {
            insert(node->left, value);
        } else if (value > node->data) {
            insert(node->right, value);
        }
    }

    static void inOrder(const BSTNode* node) {
        if (!node) return;
        inOrder(node->left.get());
        cout << ' ' << node->data;
        inOrder(node->right.get());
    }

public:
    void insert(int value) { insert(root, value); }
    void printInOrder() const {
        cout << "BST In-order:";
        inOrder(root.get());
        cout << '\n';
    }
};

class Graph {
    vector<vector<int>> adj;

    string labels;

    void dfsVisit(int u, vector<bool>& visited) const {
        visited[u] = true;
        cout << ' ' << labels[u];
        for (int v : adj[u]) {
            if (!visited[v]) dfsVisit(v, visited);
        }
    }

public:
    explicit Graph(const string& names) : adj(names.size()), labels(names) {}

    void addEdge(int u, int v) {
        adj[u].push_back(v);
        adj[v].push_back(u); // Undirected edge
    }

    void BFS(int start) const {
        vector<bool> visited(adj.size(), false);
        queue<int> pending;
        visited[start] = true;
        pending.push(start);

        cout << "BFS:";
        while (!pending.empty()) {
            int u = pending.front();
            pending.pop();
            cout << ' ' << labels[u];
            for (int v : adj[u]) {
                if (!visited[v]) {
                    visited[v] = true;
                    pending.push(v);
                }
            }
        }
        cout << '\n';
    }

    void DFS(int start) const {
        vector<bool> visited(adj.size(), false);
        cout << "DFS:";
        dfsVisit(start, visited);
        cout << '\n';
    }
};

int main() {
    BST tree;
    for (int value : {50, 30, 70, 20, 40, 60, 80}) tree.insert(value);
    tree.printInOrder();

    // A = 0, B = 1, C = 2, D = 3, E = 4. Visit neighbors in insertion order.
    Graph graph("ABCDE");
    graph.addEdge(0, 1); // A-B
    graph.addEdge(0, 2); // A-C
    graph.addEdge(1, 3); // B-D
    graph.addEdge(2, 3); // C-D
    graph.addEdge(3, 4); // D-E
    graph.BFS(0);
    graph.DFS(0);
}
