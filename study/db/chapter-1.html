البلوك الأول (Block 1) Basic Definitions: Data, Mini-World & Database

المفاهيم الأساسية: البيانات (Data)، العالم المصغر (Mini-World)، وقاعدة البيانات (Database)

💡

1. الفكرة بالبلدي (سطرين بالعدد):

أنت كمهندس مش بتسجل الكوكب كله؛ بتنقي حتة معينة من الواقع اسمها Mini-World. شوية الحقائق اللي بتسجلها عن الحتة دي اسمها Data، ولما ترتبهم برباط وعلاقة منطقية لغرض واضح بيبقوا Database.

2. نصوص السلايد الرسمية + التوضيح بالعامية:

أولاً: البيانات Data

Official Slide Text: Data: Known facts that can be recorded and have an implicit meaning.
• التوضيح بالعامية: أي معلومة أو حقيقة نقدر نسجلها ويكون ليها معنى مفهوم ضمنياً في سياقها (زي اسمك، سنك، درجاتك).

ثانياً: العالم المصغر Mini-World / Universe of Discourse - UoD

Official Slide Text: Mini-World (or Universe of Discourse - UoD): Some part of the real world about which data is stored in a database (e.g., student grades and transcripts at a university). Changes to the mini-world are reflected in the database.
• التوضيح بالعامية: حتة الواقع اللي عينك عليها وبتعملها السيستم (مستشفى، جامعة)، وأي تغيير بيحصل في الواقع (طالب انسحب مثلاً) لازم يسمع فوراً في الداتابيز.

ثالثاً: قاعدة البيانات وخواصها الأربعة Database

Official Slide Text:

Database: A collection of related data.

  • Represents some aspect of the real world (Mini-world / UoD).
  • Logically coherent collection of data with inherent meaning (random data cannot correctly be referred to as a database).
  • Designed, built, and populated with data for a specific purpose.
  • Has an intended group of users and preconceived applications.
• التوضيح بالعامية: مش شوية ملفات محطوطة جنب بعض وخلاص؛ دي بيانات بينها علاقة وترابط منطقي، اتصممت واتملت داتا لغرض محدد ولمستخدمين محددين.

البلوك الثاني (Block 2) DBMS Functions, Environment & Meta-data Catalog

نظام الـ DBMS، وظائفه الأربعة، بيئته الكاملة، والـ Meta-data & Catalog

💡

1. الفكرة بالبلدي (ملخص البلوك والـ Meta-data):

الـ DBMS مش ملف عادي، ده "البرنامج الوسيط الكبير" (زي Oracle أو MySQL). عشان يدير قاعدة البيانات، بيمشي في 4 خطوات إجبارية بالترتيب: يحدد شهادة ميلاد الجداول والقيود (Defining)، يخزنها على الهارد (Constructing)، يستقبل طلبات البحث والتعديل اليومية (Manipulating)، ويسمح لكذا يوزر وبرنامج يفتحوا مع بعض في نفس الثانية بأمان تام (Sharing).

أما الـ Meta-data ببساطة فهي "بيانات بتوصف البيانات". يعني لو جدول الطلاب فيه اسمك وسنك، الميتا داتا مش اسمك، الميتا داتا هي السطر اللي بيقول: "الاسم ده نوعه نص وحجمه 30 حرف، والسن ده رقم ومينفعش يبقى سالب". الكشكول اللي متجمعة فيه كل الميتا داتا دي جوه الـ DBMS اسمه الـ Catalog (أو Data Dictionary).

2. تعريف الـ DBMS والوظائف الأربعة الأساسية بالتفصيل:

تعريف نظام إدارة قواعد البيانات DBMS (Database Management System)

A collection of programs that enables users to create and maintain a database. The DBMS is a general-purpose software system that facilitates the processes of defining, constructing, manipulating, and sharing databases among various users and applications.

• بالعامية: سوفت وير عام بيقعد في النص بين المستخدم والداتا اللي على الهارد، مهمته ينشئ الداتابيز ويحافظ عليها وينفذ الوظائف الأربعة دول:

1

تعريف قاعدة البيانات Defining a Database

Involves specifying the data types, structures, and constraints of the data to be stored in the database.

• بالعامية: كتابة شهادة ميلاد الداتا؛ بنحدد اسم كل جدول، أسماء العواميد، نوع كل بيان (نصوص، أرقام، تواريخ)، والشروط والقيود (زي: رقم الطالب ميتكررش، والمرتب أكبر من الصفر).

2

بناء وتخزين قاعدة البيانات Constructing the Database

The process of storing the data on some storage medium that is controlled by the DBMS.

• بالعامية: نقل الداتا من مجرد كلام وتصميم إلى كتابتها وحفظها فعلياً على وسيط تخزين (زي الهارد ديسك أو SSD) تحت سيطرة محرك الـ DBMS.

3

التعامل مع البيانات ومعالجتها Manipulating a Database

Functions such as querying the database to retrieve specific data, updating the database to reflect changes in the mini-world, and generating reports from the data.

• بالعامية: الشغل اليومي مع البيانات: استعلام وبحث (Query)، تعديل وإضافة ومسح لمواكبة اللي بيحصل في الواقع (Update)، واستخراج وطباعة تقارير للمستخدمين (Generating Reports).

4

مشاركة قاعدة البيانات Sharing a Database

Allows multiple users and programs to access the database concurrently.

• بالعامية: إن كذا موظف وكذا برنامج يدخلوا في نفس اللحظة بالمللي ثانية يقروا ويعدلوا من غير ما حد يمسح شغل التاني.

وظائف الحماية والصيانة الإضافية (Protection & Maintenance):

• System Protection: Protection against hardware or software malfunction (crashes).

• Security Protection: Protection against unauthorized or malicious access.

• Maintenance (System Evolution): Maintaining the database system by allowing the system to evolve as requirements change over time.

  • • حماية النظام (System Protection): حماية السيستم ضد الانهيار الفني لو النور قطع أو الهارد عطل.
  • • الحماية الأمنية (Security Protection): حماية أمنية بالباسوردات والصلاحيات لمنع المتطفلين والمخترقين.
  • • الصيانة والتطور (Maintenance): عشان السيستم يقدر يكبر ويتعدل مع مرور السنين حسب احتياج المؤسسة.

تفاعل التطبيقات مع الـ DBMS (Application Activities Against a Database):

Applications interact with a database by generating:

1. Queries: Access different parts of data and formulate the result of a request.

2. Transactions: May read some data and "update" certain values of documents in the database, and generate new data and store that.

• Applications must not allow unauthorized users to access data & must keep up with changes in the database schema over time.

• بالعامية: البرامج بتكلم الداتابيز بطريقتين: يا إما بتبعت Query عشان تقرا وتسترجع معلومة معينة، أو بتبعت Transaction عشان تقرا وتعدل وتسجل داتا جديدة (زي سحب وإيداع فلوس).

🏛️ رسمة معمارية مرسومة: بيئة نظام قاعدة البيانات المبسطة (Simplified Database System Environment)

رسم تفاعلي كامل من القمة للقاع كما في السلايد

3. الـ Meta-data، الكتالوج (DBMS Catalog)، والطبيعة الذاتية الوصف:

الـ Meta-data والـ DBMS Catalog (Data Dictionary)

Meta-data: Data that describes the structure of the primary database; data about data. It includes the description of the database structure, data types, field lengths, and constraints.

The DBMS Catalog: Stores the description of a particular database (e.g. data structures, types, and constraints) to be accessed by the DBMS software or database users where needed.

Self-Describing Nature: A database system contains not only the database itself, but also a complete definition of the database structure and constraints. In traditional file processing, data definition is typically part of the application programs themselves.

• بالعامية: زمان ملف التكست مكانش فاهم نفسه؛ البرنامج هو اللي بيشرحه. في الـ DBMS، النظام بيوصف نفسه بنفسه لأن الكتالوج شايل الميتا داتا جواه. ده بيخلي الـ DBMS برنامج عام يشتغل مع أي داتابيز في الدنيا بمجرد قراءة كتالوجها!

البلوك الثالث (Block 3) Types of Databases & Traditional vs Recent Applications

أنواع قواعد البيانات وتطبيقاتها التقليدية والحديثة + محركات البحث والـ Cloud

💡

1. الفكرة بالبلدي (سطرين بالعدد):

قواعد البيانات زمان بدأت بتخزين أرقام ونصوص عادية لجداول الموظفين والحسابات (Traditional). مع التطور، ظهرت أنواع متوحشة جديدة بتخزن صور وفيديوهات، وخرائط GPS، وشبكات الجينات البشرية، وتغريدات وبوستات السوشيال ميديا بالمليارات (Recent Applications).

🧭 خريطة بصرية مرسومة: مقارنة التطبيقات التقليدية بالتطبيقات الحديثة والتطورات السحابية

2. تفاصيل كل نوع بنص السلايد والتوضيح بالعامية (واحدة تلو الأخرى):

• التطبيقات التقليدية Traditional Applications

Traditional Applications: Numeric and Textual Databases.

• بالعامية: الشغل الكلاسيكي البسيط: أرقام ونصوص (جداول موظفين، حسابات بنوك، كشوف مرتبات).

1. قواعد بيانات المالتيميديا Multimedia Databases

Can store images, audio clips, and video streams digitally.

• بالعامية: بتخزن صور، مقاطع صوت، وفيديوهات (زي منصات يوتيوب ونتفلكس وأنظمة المراقبة بالكاميرات).

2. نظم المعلومات الجغرافية Geographic Information Systems - GIS

Can store and analyze maps, weather data, and satellite images.

• بالعامية: بتخزن وتدير الخرائط، إحداثيات المواقع (GPS)، بيانات الطقس، وصور الأقمار الصناعية (زي Google Maps).

3. قواعد البيانات الحيوية والجينية Biological and Genome Databases

Store biological data such as genetic codes, DNA sequences, and protein structures from molecular biology research.

• بالعامية: بتخزن سلاسل الحمض النووي (DNA)، الشفرات الوراثية، وتركيبات البروتين المعقدة للأبحاث العلمية.

4. مستودعات البيانات والبيانات الضخمة Data Warehouses & Big Data Systems

Used to aggregate and extract information from multiple very large databases for decision making, Business Intelligence (BI), and online analytical processing (OLAP).

• بالعامية: مخازن عملاقة بتسحب البيانات القديمة والتاريخية من كل فروع الشركة عشان المديرين يحللوها وياخدوا قرارات استراتيجية.

5. شبكات التواصل الاجتماعي Social Networks / Real-time Web

Capturing a lot of information about people and communications among people: posts, tweets, photos, videos (Facebook, Twitter).

• بالعامية: أنظمة زي فيسبوك وإكس بتسجل مليارات البوستات والتغريدات وعلاقات الصداقة والمتابعة في اللحظة والتو.

6. محركات البحث كقواعد بيانات حديثة Search Engines & Web Search

Search Engines: Search engines such as Google and Yahoo! capture a lot of textual data and non-textual data from the World Wide Web and provide search capabilities that are now part of our everyday life.

• بالعامية: محركات البحث (زي جوجل) بتعمل الزحف (Crawling) على الإنترنت كله وتجمع مليارات النصوص والصفحات وتفهرسها في قواعد بيانات عملاقة عشان ترجعلك النتيجة في جزء من الثانية.

7. الحوسبة السحابية وتخزين البيانات الضخمة Cloud Storage & Big Data

• Databases are being moved to the Cloud by major cloud computing providers (e.g., Amazon AWS, Microsoft Azure, Google Cloud).

• Big Data Storage: Massive amounts of data generated from social networks, web search, mobile apps, and sensors that traditional relational databases could not handle efficiently.

• بالعامية: زمان كانت الداتابيز بتتحط على سيرفر حديد جوه أوضة في الشركة. دلوقتي الداتابيز بتترفع على السحابة (Cloud)، والبيانات الضخمة الناتجة من الموبايلات والحساسات (Sensors) عملت ثورة الـ Big Data.

البلوك الرابع (Block 4) Main Characteristics of the Database Approach

الخصائص الجوهرية الأربعة لمدخل قواعد البيانات مقابل نظام الملفات القديم

💡

1. الفكرة بالبلدي (سطرين بالعدد):

زمان، أنظمة الملفات العادية كانت مأساة: كود البرنامج محشور جواه شكل الملفات، وكل يوزر محبوس في ملفه، ومفيش اتنين يقدروا يعدلوا مع بعض. الـ DBMS جه قلب الترابيزة بـ 4 أسلحة سحرية: وصف نفسه بنفسه بالكتالوج، فصل كود البرامج عن شكل التخزين، عمل شاشات ورؤى مخصصة لكل يوزر، ونظم دخول آلاف المستخدمين مع بعض في نفس الثانية بدون تضارب.

🛡️ رسمة توضيحية مرسومة: الأركان الأربعة لمدخل قواعد البيانات مقارنة بالملفات التقليدية

2. نصوص السلايد الرسمية + التوضيح بالعامية للخصائص الأربعة:

الخاصية 1: طبيعة النظام في وصف نفسه Self-Describing Nature of a Database System

• Traditional file processing: Data definition is part of the application programs themselves.

• Database approach: The DBMS catalog stores the description of the particular database (e.g., data structures, types, and constraints). This information is called meta-data.

• This allows the DBMS software to work with different database applications.

• بالعامية: ملف التكست أو الإكسيل القديم ملف أعمى؛ كود البرنامج هو اللي شايل تفاصيل التقسيمة. في الـ DBMS، مواصفات الجداول متسجلة في كتالوج مركزي مستقل اسمه Catalog كـ Metadata. الميزة العظمى؟ محرك الـ DBMS برنامج عام يقدر يشتغل مع جامعة، بنك، أو مستشفى بمجرد ما يقرأ كتالوجها.

الخاصية 2: استقلالية البيانات عن البرامج وحجب التفاصيل Insulation between Programs and Data & Data Abstraction

• Program-Data Independence: The structure of data files is stored in the DBMS catalog separately from the access programs. Changes to the structure of data do not require changing the programs that access it.

• Program-Operation Independence: User application programs can operate on the data by invoking operations (methods) through their interface, without knowing how the operations are implemented.

• Data Abstraction: The characteristic that allows program-data independence and program-operation independence. A conceptual representation of data does not include many of the storage details.

• Data Model: A type of data abstraction that is used to provide this conceptual representation.

  • • Program-Data Independence: شكل وحجم العواميد مفصول عن كود البرامج؛ فلو وسعنا خانة التليفون أو ضفنا عمود جديد في الجدول، البرامج اللي بتستخدم الداتابيز تفضل شغالة من غير ما نغير فيها سطر كود واحد!
  • • Program-Operation Independence: أنت بتنادي العملية بالاسم (زي: احسب المرتب أو اعرض الاسم) من خلال الواجهة (Interface) من غير ما يخصك الكود الداخلي متنفذ إزاي (Implementation).
  • • Data Abstraction: حجب تفاصيل التخزين والتعقيد عن المستخدم والمبرمج، وده بيتحقق عن طريق نموذج البيانات (Data Model).

الخاصية 3: تعدد واجهات الرؤية للبيانات Support of Multiple Views of the Data

• A database typically has many types of users, each of whom may require a different perspective or view of the database.

• A View may be a subset of the database, or it may contain virtual data that is derived from the database files but is not explicitly stored.

• Example: A student's GPA or Course Transcript calculated dynamically.

• بالعامية: كل موظف أو طالب بيدخل بيشوف شاشة مفصلة على مقاسه (موظف شؤون الطلاب يشوف الدرجات، والحسابات تشوف المصاريف). الـ View ممكن تكون عمود مش متخزن فعلياً في الهارد، لكن محسوب بالمعادلة في اللحظة دي كـ داتا افتراضية (Virtual Data) زي حساب الـ GPA أو سن الطالب من تاريخ ميلاده.

الخاصية 4: مشاركة البيانات ومعالجة المعاملات لعدة مستخدمين Sharing of Data & Multiuser Transaction Processing

• A multiuser DBMS must allow multiple users to access the database at the same time.

• Concurrency Control Software: Ensures that several users trying to update the same data do so in a controlled manner so that the result of the updates is correct.

• Transaction: An executing program or process that includes one or more database accesses (such as reading or updating records).

• Isolation Property: Each transaction appears to execute in isolation from other transactions, even though hundreds may be executing concurrently.

• Atomicity Property: Ensures that either all the database operations in a transaction are executed or none are.

  • • Concurrency Control Software: حارس بيمنع تضارب العمليات لما آلاف الناس تحجز تذاكر طيران أو تسحب من الـ ATM في نفس اللحظة.
  • • Atomicity (الذرية / الكل أو لا شيء): لو بتحول فلوس من حساب لحساب، لازم السحب والإيداع يتموا مع بعض؛ لو السيرفر فصل في النص، العملية تتلغي كلها كأنها مابدأتش.
  • • Isolation (العزل): المعاملة تتنفذ في معزل عن باقي المعاملات، ومتحسش بحد شغال معاها على نفس السيستم.

البلوك الخامس (Block 5) Database Users: Actors on the Scene vs Behind the Scene

مستخدمو قواعد البيانات: أبطال على المسرح (On the Scene) وأبطال خلف الكواليس (Behind the Scene)

💡

1. الفكرة بالبلدي (سطرين بالعدد):

الناس اللي ليهم علاقة بالداتابيز نوعين مفيش غيرهم: أبطال على المسرح (On the Scene) دول اللي شغالين في شركتك وبيتفاعلوا مع الداتابيز بتاعتك فعلياً، وأبطال خلف الكواليس (Behind the Scene) دول مش شغالين عندك أصلاً، دول العباقرة اللي اخترعوا وصنعوا سوفت وير الـ DBMS ومحركه ذات نفسه في شركات زي أوراكل وميكروسوفت.

🎭 رسمة تقسيمية مرسومة: مسرح مستخدمي قواعد البيانات (On the Scene vs Behind the Scene)

2. الفئة الأولى: أبطال على المسرح (Actors on the Scene):

1. مدير قاعدة البيانات Database Administrator - DBA

• Responsible for authorizing access to the database.

• Coordinating and monitoring its use.

• Acquiring software and hardware resources as needed.

• Accountable for problems such as security breaches and poor system response time.

• بالعامية: الكل في الكل ورئيس جمهورية الداتابيز: بيعمل الحسابات والباسوردات ويدي الصلاحيات، بيراقب سرعة السيستم ولو السيرفر بطيء بيتحاسب، ومسؤول عن النسخ الاحتياطية (Backups) وحماية الداتابيز من الاختراق.

2. مصممو قاعدة البيانات Database Designers

• Responsible for identifying the data to be stored in the database and choosing appropriate structures to represent and store this data.

• Communicating with all prospective database users in order to understand their requirements.

• Typically perform their tasks BEFORE the database is actually implemented and populated.

• بالعامية: المهندسين المعماريين بتوع الداتابيز؛ بيقعدوا مع العملاء والموظفين قبل ما نكتب أي كود، يفهموا طلباتهم، ويصمموا الجداول والـ ER Diagrams، وشغلهم بينتهي أول ما الداتابيز تتنفذ وتتملى بيانات.

3. المستخدمون النهائيون بأصنافهم الأربعة End Users (4 Types)

هم الأشخاص اللي طبيعة شغلهم بتتطلب الدخول للداتابيز للاستعلام والتحديث والتقارير، وينقسمون إلى:

أ. المستخدم السطحي / النمطي Parametric / Naive End Users

Make up a sizable portion of database end users. Constantly querying and updating using standard pre-programmed queries called canned transactions (e.g., Bank tellers, Reservation clerks).

• بالعامية: موظف الشباك في البنك أو حجز الطيران اللي بيتعامل مع أزرار جاهزة وشاشات ثابتة (Canned Transactions) مبيدخلش يكتب SQL.

ب. المستخدم العارض Casual End Users

Occasionally access the database, but they may need different information each time (e.g., Middle- or high-level managers).

• بالعامية: مدير بيفتح السيستم مرة كل أسبوع أو شهر عشان يطلب إحصائية جديدة ومختلفة عن المرة اللي فاتت.

ج. المستخدم المتطور Sophisticated End Users

Include engineers, scientists, business analysts who thoroughly familiarize themselves with the facilities of the DBMS to implement complex applications.

• بالعامية: باحثين ومهندسين ومحللي بيانات فاهمين الـ DBMS كويس جداً، بيكتبوا كويريهات معقدة وتحليلات عميقة بنفسهم.

د. المستخدم المستقل Standalone End Users

Maintain personal databases by using ready-made program packages that provide easy-to-use menu-driven interfaces (e.g., tax program user).

• بالعامية: شخص شغال مع برنامج ضرائب شخصي جاهز على جهازه لوحده معندوش شبكة ولا مشاركة مع حد.

4. محللو النظم ومطورو البرامج System Analysts & Application Programmers (Software Engineers)

• System Analysts: Determine the requirements of end users, especially naive and parametric users, and develop specifications for standard canned transactions.

• Application Programmers: Implement these specifications as programs; then they test, debug, document, and maintain these canned transactions.

• بالعامية: محلل النظم بيفهم احتياج موظف الشباك ويحدد المواصفات، والمبرمج يكتب الكود ويبرمج الـ Canned Transactions ويجربها ويصلح أخطائها.

3. الفئة الثانية: أبطال خلف الكواليس (Actors behind the Scene):

1. مصممو ومبرمجو نظام الـ DBMS نفسه DBMS System Designers and Implementers

Design and implement the DBMS modules and interfaces as a software package (compilers, query execution engines, buffers).

• بالعامية: المهندسين اللي كتبوا كود محرك قواعد البيانات الداخلي نفسه في شركات زي Oracle و Microsoft و MySQL.

2. مطورو الأدوات المساعدة Tool Developers

Design and implement tools—software packages that facilitate database modeling, design, performance monitoring, and GUI.

• بالعامية: الشركات أو المطورين اللي بيعملوا برامج ملحقة مساعدة بتساعد مصمم الداتابيز (زي برامج رسم الـ ER أو فحص سرعة السيرفرات).

3. مشغلو النظام وعمال الصيانة Operators and Maintenance Personnel

Responsible for the actual running and maintenance of the hardware and software environment for the database system.

• بالعامية: مهندسو وفنيو السيرفرات والشبكات والداتا سنتر اللي بيضمنوا إن الكهربا والتبريد والهاردوير شغالين بدون توقف.

البلوك السادس (Block 6) Advantages of DBMS, Implications & When NOT to Use

مميزات الـ DBMS التسعة، الفوائد الإدارية، ومتى نتجنب استخدامه؟

💡

1. الفكرة ��البلدي (سطرين بالعدد):

الـ DBMS مش مجرد برنامج تخزين، ده بيوفر حزمة مميزات ضخمة للمؤسسات: بيقضي على تكرار البيانات، وبيضمن الأمان والنسخ الاحتياطي، وبيطبق القواعد أوتوماتيكياً. لكن في المقابل، ليه تكلفة واستهلاك موارد (Overhead)؛ فلو برنامجك بسيط جداً أو محتاج سرعة فائقة بالنانو ثانية، الـ DBMS هيبقى عبء وخسارة ونظام الملفات العادي يكسب!

2. مميزات استخدام الـ DBMS التسعة (Advantages of Using the Database Approach):

1. التحكم في تكرار البيانات Controlling Redundancy

In traditional file processing, duplication leads to wasted storage and data inconsistency. DBMS enforces controlled redundancy when needed for performance.

• بالعامية: يمنع تكرار البيانات وتناقضها (Inconsistency)، ولو اضطرينا نكرر لسرعة الأداء، الـ DBMS بنفسه بيحافظ على تناسق التكرار أوتوماتيكياً.

2. منع الوصول غير المصرح به Restricting Unauthorized Access

Security and authorization subsystem creates accounts and specifies privileges on who can read/modify data.

• بالعامية: نظام أمان متكامل بالباسوردات والصلاحيات لكل مستخدم.

3. توفير مساحات تخزين دائمة لكائنات البرمجة Persistent Storage for Program Objects

Object-Oriented DBMSs directly store C++/Java objects permanently without impedance mismatch.

• بالعامية: بيخزن كائنات لغات البرمجة (Objects) زي ما هي على الهارد بشكل دائم.

4. توفير فهارس وهياكل لتسريع الاستعلامات Storage Structures for Efficient Query Processing

DBMS provides auxiliary files called indexes and buffering techniques to speed up disk searches.

• بالعامية: بيعمل فهارس (Indexes) ومسارات سريعة في الذاكرة (Buffering) عشان تلاقي السجل في جزء من الثانية.

5. النسخ الاحتياطي واستعادة البيانات بعد الانهيار Backup and Recovery

Responsible for recovery if the system crashes in the middle of a complex update transaction.

• بالعامية: لو النور قطع في نص عملية تحويل فلوس، السيستم بيرجع أوتوماتيك لآخر نقطة سليمة.

6. توفير واجهات مستخدم متعددة Providing Multiple User Interfaces

Query languages for casual users, programming APIs for developers, forms/menus for naive users.

• بالعامية: كل يوزر ليه الواجهة اللي تناسبه سواء شاشات وأزرار أو كتابة كود.

7. تمثيل العلاقات المعقدة بين البيانات Representing Complex Relationships

Easily defining and maintaining complex links between related entities and records.

• بالعامية: ربط الجداول ببعضها مهما كانت معقدة.

8. فرض قيود السلامة وصحة البيانات Enforcing Integrity Constraints

Constraints must hold for data (data type, unique keys, referential integrity). DBMS automatically checks updates.

• بالعامية: شروط بيكتبها المصمم والـ DBMS بيجبر السيستم يطبقها أوتوماتيكياً (زي عدم تكرار الـ ID).

9. السماح بالاستنتاج والعمليات التلقائية Permitting Inferencing & Actions Using Rules (Triggers)

Deductive databases deduce new facts; Active databases use Triggers to execute actions automatically.

• بالعامية: لو رصيد العميل نزل عن الصفر، السيستم أوتوماتيكياً يبعتله رسالة عن طريق الـ Triggers.

ثانياً: الفوائد الإدارية والاقتصادية الـ 5:

  • 1. Enforcing Standards: توحيد المعايير في تسمية العواميد وشكل البيانات في كل الشركة.
  • 2. Reduced Application Development Time: تقليل وقت برمجة التطبيقات الجديدة.
  • 3. Flexibility: مرونة تعديل هيكل الجداول مع تغير احتياجات الشغل.
  • 4. Availability of Up-to-Date Info: أي تعديل بيظهر فوراً لكل المستخدمين في نفس اللحظة.
  • 5. Economies of Scale: توفير الفلوس والأجهزة بدمج احتياجات المؤسسة كلها في نظام موحد.

ثالثاً: متى لا نستخدم الـ DBMS؟ (When NOT to Use):

بسبب التكلفة العالية (High initial investment) وعبء المعالجة (Overhead)، نفضل نظام الملفات العادي في 4 حالات:

  • 1. Simple, well-defined applications: تطبيقات بسيطة ومحددة ومش هتتغير.
  • 2. Stringent real-time requirements: أنظمة حرجة بالنانو ثانية (توجيه صواريخ / أجهزة طبية) متستحملش بطء الـ DBMS.
  • 3. Embedded systems with limited storage: أجهزة مدمجة بمساحة ورامات صغيرة جداً.
  • 4. No multiple-user access needed: برنامج لشخص واحد فقط لا يحتاج مشاركة.
إضافات السلايدات الهامة (Extra Highlights) Normalization, Business Analysts, Query Optimizer & University Schema

النقاط الخمس الذهبية الإضافية + رسمة قاعدة بيانات الجامعة (UNIVERSITY Database)

1. مصطلح التطبيع ومنع التكرار Data Normalization (Slide 25)

Each logical data item (such as a student’s name or birth date) is stored in only one place in the database. This is known as data normalization, and it ensures consistency and saves storage space.

• بالعامية وفخ الامتحان: تخزين كل معلومة منطقية في مكان واحد فقط لمنع التناقض وتوفير المساحة اسمه Data Normalization.

2. محللو الأعمال Business Analysts (Slide 23)

Business Analysts: Analyze vast amounts of business data and real-time data (“Big Data”) for better decision making related to planning, advertising, and marketing.

• بالعامية وفخ الامتحان: ينتمون إلى Actors ON the Scene (وليس Behind the scene)، ووظيفتهم تحليل الـ Big Data لقرارات التسويق والتخطيط.

3. موديول تحسين الاستعلامات Query Processing & Optimization Module (Slide 26)

The query processing and optimization module of the DBMS is responsible for choosing an efficient query execution plan for each query based on the existing storage structures (e.g., indexes).

• بالعامية: العقل الذكي جوه الـ DBMS اللي بيختار أسرع خطة تنفيذ (Execution Plan) بالاعتماد على الفهارس.

4. تقليل وقت بناء التطبيقات الإضافية Incremental Development Time (Slide 28)

Reduced application development time: Once a database is up and running, the incremental time to add each new application is significantly reduced.

• بالعامية: طالما الداتابيز اتبنت، إضافة أي برنامج جديد للشركة بياخد وقت قليل جداً.
