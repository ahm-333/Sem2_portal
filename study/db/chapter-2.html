1. تجريد البيانات ونماذج البيانات (Data Abstraction & Data Models)

1.1 تجريد البيانات (Data Abstraction)

Slide 3 Official Academic Text: • Suppression of details of data organization and storage.
• Highlighting of the essential features for an improved understanding of data.

💡 الفكرة بالبلدي الفصيح:

الكمبيوتر في الأصل بيتعامل مع أصفار ووحايد، بلوكات ومسارات مغناطيسية على القرص الصلب (Hard Disk). لو كل مبرمج أو مستخدم شال هم مكان البايت فين ورقم القطاع كام، مستحيل حد يقدر يبني أي برنامج!

عشان كده نظام الـ DBMS بيعمل حاجتين عبقريتين:

  • كبت وإخفاء التفاصيل (Suppression of details): يخفي تماماً طريقة التخزين المعقدة في الـ Hard Drive.
  • إبراز الخصائص الجوهرية (Highlighting essential features): يظهرلك بس اللي يهمك كإنسان: "فيه جدول اسمه طالب، فيه عمود اسم ورقم ومعدل".
  • النتيجة النهائية: فهم أفضل وأسهل للبيانات بمراحل (Improved understanding).

1.2 ما هو نموذج البيانات؟ (What is a Data Model?)

Slide 4 Official Academic Text: • Collection of concepts that describe the structure of a database.
• Provides means to achieve data abstraction.
• Basic operations: Specify retrievals and updates; the dynamic aspect or behavior of a database application.
• Example of user-defined operation: COMPUTE_GPA applied to a STUDENT object.

الـ Data Model هو الكتالوج والأداة اللي بنحقق بيها تجريد البيانات. وهو عبارة عن مجموعة مفاهيم بتوصف هيكل قاعدة البيانات (Structure) عبر 3 مكونات:

1. أنواع البيانات Data Types (أرقام، نصوص، تواريخ، ملفات).
2. العلاقات Relationships (الروابط بين الكيانات والجداول).
3. القيود والشروط Constraints (الـ Primary Key، عدم التكرار، والمدى).

📌 تريكة السلايد: نموذج البيانات مش مجرد هيكل ثابت ميت! هو بيحدد كمان الجانب الديناميكي أو السلوك (Dynamic aspect / behavior) عن طريق تحديد عمليات الاسترجاع والتحديث وعمليات خاصة يحددها المصمم، ومثال السلايد الرسمي: دالة COMPUTE_GPA التي تحسب المعدل لكائن الطالب.

1.3 الفئات الثلاث لنماذج البيانات (Categories of Data Models)

السلايدات 5 إلى 10 بتقسم نماذج البيانات لـ 3 مستويات حسب قربها من فهم الإنسان أو قربها من عتاد التخزين:

الفئة 1 • الأقرب للإنسان 🧠

النموذج المفاهيمي عالي المستوى

High-level or Conceptual

أقرب ما يكون لطريقة إدراك وفهم البشر للبيانات في الواقع (Close to user perception).

مفاهيمه الثلاثة (سلايد 6):

• Entity (الكيان): شيء واقعي (طالب، موظف).

• Attribute (الخاصية): صفة بتوصف الكيان (الاسم، العمر).

• Relationship (العلاقة): رابطة بين الكيانات (الطالب يسجل في كورس).

مثاله الرسمي: نموذج ER Model
الفئة 2 • حلقة الوصل ⚖️

النموذج التمثيلي / التطبيقي

Representational / Implementation

حلقة وصل: سهل على المستخدم يفهمه، وفي نفس الوقت متطابق مع طريقة تنظيم الملفات في الكمبيوتر.

أهم نوعين (سلايد 7 و 8):

• Relational Data Model: الأكثر انتشاراً في الـ DBMS التجاري، ويمثل البيانات في جداول وسجلات، لذا يسمى Record-based.

• Object Data Model: عائلة حديثة أقرب للـ Conceptual وللـ OOP.

مثاله الرسمي: Relational Model (SQL)
الفئة 3 • الأقرب للهاردوير 💾

النموذج الفيزيائي منخفض المستوى

Low-level or Physical

بيوصف التفاصيل الدقيقة لكيفية حفظ وتخزين الملفات على الأقراص الصلبة (شكل السجلات، ترتيبها، ومسارات الوصول).

أهم مفهومين (سلايد 9):

• Access Path (مسار الوصول): هيكل برمجي يجعل البحث عن السجلات فائق السرعة والكفاءة.

• Index (الفهرس): مثال مباشر لمسار الوصول يتيح البحث بمفتاح زي فهرس الكتاب.

مثاله الرسمي: مسارات الوصول والفهارس

2. المخطط، الحالة، واللقطة (Schemas, Instances, and Database State)

ده قلب أسئلة الامتحانات! الدكتور في السلايد بيفرق بدقة رياضية شديدة بين الهيكل النظري الثابت وبين البيانات الحية المتغيرة كل ثانية:

الهيكل النظري Intension

مخطط قاعدة البيانات (Database Schema)

• Description of a database specified during database design.
• Is not expected to change frequently.
• Also called Intension.
  • Schema Diagram (رسمة المخطط): رسمة بتعرض هيكل الجداول وأسمائها وحقولها، لكن لا تعرض أي سجلات فعلية نهائياً!
  • Schema Construct (عنصر المخطط): كل كائن أو جدول داخل المخطط زي STUDENT أو COURSE.
  • Schema Evolution (تطور المخطط): التعديلات النادرة جداً اللي بتتعمل لما متطلبات السيستم تتغير (زي إضافة عمود جديد).
البيانات الحية Extension

حالة قاعدة البيانات (Database State / Snapshot)

• Refers to the content of a database at a moment in time.
• The actual data stored in a database at a particular moment.
• Every time an update is applied, we get another database state.
• Also called Extension or Instance or Snapshot.
  • Initial State (الحالة المبدئية): أول ما بنبني الداتابيز ونحمل فيها أول دفعة داتا.
  • Valid State (الحالة الصالحة): حالة بتحترم كل القيود والشروط والـ DBMS بيضمن بقاء الداتابيز صالحة دائماً.
  • الـ State بتتغير مع كل عملية إضافة أو حذف أو تعديل تجري على أي جدول!

📌 الجدول الذهبي للمقارنة الحاسمة (من سلايد 15):

وجه المقارنة Database Schema (المخطط) Database State (الحالة)
المعنى الجوهري وصف وتصميم وهيكل البيانات (Description) المحتوى والبيانات الفعلية في لحظة معينة (Content)
معدل التغيير يتغير نادراً جداً (Changes very infrequently) يتغير باستمرار مع كل تحديث (Changes with every update)
الاسم العلمي البديل Intension Extension (أو Snapshot أو Instance)
وقت التحديد أثناء مرحلة التصميم وبناء النظام (Design Phase) أثناء تشغيل النظام الفعلي على مدار اليوم (Runtime)

📊 مثال السلايدات الرسمي المقارن (جامعة UNIVERSITY):

1. Schema Diagram (سلايد 12: هيكل فقط بلا داتا)
STUDENT Name | Student_number | Class | Major
COURSE Course_name | Course_number | Credit_hours | Department

مفيش أي طالب حقيقي هنا؛ مجرد حقول وأعمدة ومفاتيح أساسية مسطرة.

2. Database State (سلايد 16: السجلات الحية)
NameStudent_numClassMajor
Smith171CS
Brown82CS

دي لقطة حية (Snapshot) للسجلات المسجلة في رامات وهارد السيرفر في اللحظة دي.

3. معمارية المستويات الثلاثة واستقلالية البيانات (Three-Schema & Data Independence)

3.1 الهدف الرئيسي من معمارية المستويات الثلاثة (The Goal - سلايد 18)

Slide 18 Official Academic Goal: The goal of the three-schema architecture is to separate the user applications from the physical database.

الهدف الأسمى للمعمارية هو فصل برامج وشاشات المستخدمين تماماً عن التخزين الفيزيائي الفعلي على الهارد ديسك؛ عشان لو غيرنا مكان تخزين الملفات أو ضفنا فهارس جديدة، البرامج متتعطلش ولا تتأثر!

3.2 المستويات الثلاثة بالتفصيل الحرفي (سلايد 18 إلى 20)

1. المستوى الخارجي

External or View Level

• بيوصف جزء فقط من الداتابيز يهم مجموعة محددة من المستخدمين (Part of database).
• يخفي باقي الداتابيز عن تلك الفئة.
• مثال: شاشة موظف الخزينة يظهرله جدول المصاريف فقط ويحجب عنه درجات الطلاب ومرتبات الدكاترة.

2. المستوى المفاهيمي

Conceptual Level

• بيوصف هيكل الداتابيز كلها بالكامل لكل المستخدمين (Structure of whole database).
• يخفي تماماً تفاصيل التخزين والمسارات الفيزيائية.
• يركز على الكيانات والأنواع والعلاقات والقيود وعمليات المستخدمين (Entities, Constraints).

3. المستوى الداخلي

Internal Level

• بيوصف هيكل التخزين الفيزيائي الفعلي لقاعدة البيانات (Physical storage structure).
• يستخدم نموذج بيانات فيزيائي (Physical data model).
• بيوصف تفاصيل حفظ البيانات ومسارات الوصول والفهارس (Access paths & storage).

3.3 عمليات التحويل وإعادة التشكيل (Mappings & Reformatting - سلايد 21)

لما المستخدم يطلب داتا من شاشته الخارجية، الطلب بيعدي على طبقتين تحويل (Mappings):

1. External / Conceptual Mapping: تحويل طلب الشاشة الخارجية للمخطط المفاهيمي العام.

2. Conceptual / Internal Mapping: تحويل المخطط المفاهيمي لأوامر قراءة مباشرة من الهارد ديسك.

🚨 سؤال امتحان مؤكد: أين تتم عملية إعادة تشكيل البيانات (Reformatting) لتطابق شاشة المستخدم (مثل نتائج SQL في صفحة ويب)؟
→ عند طبقة الـ External / Conceptual Mapping.

3.4 استقلالية البيانات (Data Independence - سلايد 22)

Slide 22 Official Definition: The capacity to change the schema at one level of a database system without having to change the schema at the next higher level.
النوع الأول

استقلالية البيانات المنطقية (Logical Data Independence)

Change Conceptual → External unchanged

• نص السلايد: القدرة على تعديل المخطط المفاهيمي (Conceptual Schema) دون الحاجة لتعديل المخططات الخارجية (External Schemas) أو البرامج التطبيقية.
• مثال: ضفنا جدول جديد أو عمود جديد في قاعدة البيانات، برامج ومستخدمي الشاشات القديمة يفضلوا شغالين تماماً بدون أي تعديل في كودهم.

النوع الثاني

استقلالية البيانات الفيزيائية (Physical Data Independence)

Change Internal → Conceptual unchanged

• نص السلايد: القدرة على تعديل المخطط الداخلي والتخزين الفيزيائي (Internal Schema) دون الحاجة لتعديل المخطط المفاهيمي (Conceptual Schema).
• مثال: غيرنا الهارد ديسك، أو نقلنا ملفات الداتابيز لمسار تاني، أو بنينا فهرس جديد (Index) لتسريع البحث؛ المخطط المفاهيمي والشاشات مش هيحسوا بأي فرق إطلاقاً!

3.5 لغات نظم إدارة قواعد البيانات (DBMS Languages - سلايد 23)

DDL Data Definition Defines both schemas (تحدد المخططات)
SDL Storage Definition Specifies internal schema (التخزين الفيزيائي)
VDL View Definition Specifies user views (واجهات المستخدمين)
DML Data Manipulation Retrievals, Updates (استرجاع وتعديل)

💡 واقع اليوم العملي: في قواعد البيانات الحديثة (مثل Oracle و SQL Server و MySQL)، لغة SQL الموحدة تدمج ببراعة مهام الـ DDL والـ VDL والـ DML معاً في بيئة واحدة متكاملة.

4. معماريات نظم قواعد البيانات والـ Client/Server

1. المعمارية المركزية Centralized DBMS

المعمارية المركزية (Centralized DBMS Architecture - سلايد 24)

• نص السلايد: كل وظائف الـ DBMS، وتشغيل البرامج التطبيقية، ومعالجة واجهات المستخدمين بتتم على جهاز واحد فقط (One machine).
• شاشات الموظفين زمان كانت شاشات صامتة (Dumb terminals) بلا معالج؛ جهاز المين فريم المركزي هو اللي بيعمل كل العمليات الحسابية والتخزين.

2. معمارية المستويين Two-Tier Client/Server

معمارية العميل / الخادم ذات المستويين (2-Tier Architecture - سلايد 29)

• تم فصل العمل بين جهازين متصلين بشبكة:

العميل (Client): بيشغل واجهة المستخدم (UI) + كود التطبيق نفسه (Application Programs).
الخادم (Database Server): مسؤول عن استقبال وتنفيذ استعلامات الـ SQL وإدارة المعاملات (SQL Query Processing).

🚨 تريكة الامتحان: في معمارية الـ 2-Tier كود التطبيق نفسه (Application Program) موجود على العميل (Client) وليس السيرفر!

3. معمارية الثلاثة مستويات Three-Tier (n-Tier) Web Architecture

معمارية الويب ذات المستويات الثلاثة (Three-Tier Architecture - سلايد 30 و 31)

مع ظهور الويب وتطبيقات الإنترنت، اتفصل كود التطبيق عن جهاز المستخدم تماماً، وبقى النظام مقسوم لـ 3 طبقات:

Tier 1: Client شاشة متصفح الويب الخفيف (Thin Client / Browser) لعرض الواجهة فقط بدون أي برامج ثقيلة.
Tier 2: Application Server السيرفر الوسيط (Intermediate Layer): بيشغل كود التطبيق ويخزن قواعد العمل المعقدة (Business Rules).
Tier 3: Database Server خادم قاعدة البيانات المسؤول حصراً عن تخزين وتعديل وحماية البيانات.

🚨 سؤال الامتحان الأكيد: أين يتم تخزين وتنفيذ قواعد العمل (Business Rules) في الـ 3-Tier؟
→ في الطبقة الوسيطة: سيرفر التطبيقات (Application Server / Web Server).

6. فك شفرات وتريكات الامتحان الحرفية (Exam Cipher & Traps)

الجدول ده بيختصر أهم الكلمات المفتاحية (Triggers) اللي بتيجي بنصها في امتحانات الـ MCQs للدكتور:

العبارة الحرفية في رأس السؤال (Trigger) الإجابة الصحيحة مباشرة تريكة الخداع (The Trap)
"Suppression of details... highlighting essential features" Data Abstraction بيحط Data Model عشان تتلخبط، التجريد هو المبدأ العام.
"Specifies dynamic aspect / behavior, e.g. COMPUTE_GPA" Basic Operations of Data Model العمليات الديناميكية جزء أساسي من نموذج البيانات.
"Entity, Attribute, Relationship" Conceptual Data Models دي مفاهيم النموذج المفاهيمي عالي المستوى فقط.
"Record-based data models" Relational Data Model النموذج العلائقي يسمى Record-based.
"Structure that makes the search efficient, e.g. Index" Physical Data Model / Access Path الفهرس هو مسار وصول فيزيائي.
"Structure of each record type but NOT actual instances" Schema Diagram رسمة المخطط تعرض الهيكل فقط بلا أي سجلات.
"Schema is called... while State is called..." Intension, Extension المخطط = Intension، والحالة = Extension أو Snapshot.
"Separate user applications from physical database" Three-Schema Architecture Goal ده الهدف الأسمى لمعمارية المستويات الثلاثة.
"Change conceptual schema without changing external schemas" Logical Data Independence منطقية = تعديل Conceptual دون تأثر الشاشات الخارجية.
"Change internal schema without changing conceptual schema" Physical Data Independence فيزيائية = تعديل الهاردوير والتخزين دون تأثر المخطط.
"Stores business rules in intermediate layer" Three-Tier Architecture (Application Server) الـ Business Rules توجد في الـ Application Server.
