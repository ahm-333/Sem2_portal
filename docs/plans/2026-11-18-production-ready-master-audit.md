## 4. Partitioned line-by-line audit, holistic architecture review and scheduling

Before remediation waves mutate product code, **Argon** deploys two read-only **`Hydrogen (High)`** discovery fleets in parallel inside Wave 1 (`WP-01`), routes every verified finding through a central **Defect Ledger** using **`production-scheduling`** bottleneck sequencing, and enforces **at least two independent `Hydrogen (High)` reviewers** on every package.

### 4.1 Fleet A — Partitioned line-by-line code audit (`production-code-audit`, `7` Hydrogen High agents)

100% of active source, lesson markup, styles, tooling, CI and tests are partitioned into **seven mutually exclusive sectors**. Every agent inspects every assigned file **line-by-line** (no skipping) and outputs verifiable `file:line` findings classified `P0` (Critical) through `P3` (Low) across: logic/state bugs, race conditions, null/index-`0` boundaries, security (`innerHTML`/XSS, URL schemes, prototype pollution, CSP blockers, secrets), listener/timer/WebGL memory leaks, cyclomatic complexity/god functions, DRY/Orthogonality/ETC violations, RTL/LTR & WCAG 2.2 AA defects, dead code and untested edge branches.

### 5.2 Argon's claim, review and handback procedure

1. **Claim.** After maintainer sign-off, reference the live issue, exact base SHA, owner, files, RED scenario, acceptance rows, dependencies and relevant bundled skills. Use `codex/issue-<number>-<slug>` in its own clean worktree off the latest accepted main including its predecessors. Use GitHub-native claim/board transitions. A planning comment, proposed package, draft or running branch does not grant a second worker the same file.
2. **Check the write set.** Compare canonical, case-insensitive repository-relative paths against every active claim, including creates, renames, entrypoint wiring, tests, generated CSS/catalogs and shared config. Block on any overlap. Expand any proposed new output on GitHub *before* editing; let one serialized owner regenerate it from accepted source and recheck after integration. Unexpected build drift is evidence. Broad restores or staging generated noise can conceal a real change.
3. **Verify.** On each code issue, write an acceptance-linked failing test at the public seam, observe the intended RED, make the smallest change, observe GREEN and run the complete unfiltered `npm run verify`. For behavior-preserving extraction, run characterization tests on the base and candidate; demonstrate test sensitivity in a disposable worktree before attributing a regression fix. Evidence-only packages may report existing failures directly. Give each worker its own output directory/profile and loopback **port 0** (or assigned private URL for probes); capture the actual bound port. Running a helper that exports only `register` or `auditActionContrast` runs zero scenarios.
4. **Five-attempt silent loop.** Record command, SHA, exit status, failed assertion and correction per attempt. Diagnose; preserve expectations, data, case counts, coverage and time limits. A rerun by itself supplies diagnostic evidence. After five failed verification attempts, stop, push a Draft PR containing the exact failure, relevant logs and reproduction, and escalate on the owning issue. Never turn skipped/unavailable engines, deleted fixtures or a narrowed filter into a passing gate.
5. **Dual-reviewer independent gate (minimum `2` independent `Hydrogen High` reviewers per package).** Every completed package MUST pass **at least two separate `Hydrogen (High)` review agents** before Argon accepts it (no worker may review its own output):
   - **Reviewer 1 (`Hydrogen High` — Spec, Defect Closure & Preservation Reviewer):** Audits 100% resolution of every defect ledger ID assigned to the package, `RED → GREEN` tests, unfiltered `npm run verify` results, strict allowed-file boundaries, and unchanged cryptographic/body preservation guards.
   - **Reviewer 2 (`Hydrogen High` — System Architecture, Clean Code, Security & WCAG Reviewer):** Audits Clean Code, Clean Architecture (`Orthogonality`, `ETC`, `DRY`), security sinks/sanitization, performance budgets, RTL/LTR isolation, three-theme sync, and `WCAG 2.2 AA` compliance against the same commit `HEAD`.
   A material revision re-runs both affected reviews. Argon reconciles findings, attaches the linked PR and evidence, moves the card to `للمراجعة` and requests the other collaborator. One approved integration at a time. Workers stop before merge or publish.
6. **Triage out-of-bound findings.** Capture user impact, source/symbol and reproducible evidence, severity, affected gate, owner and retest. If fixes need a different file contract, Argon reconciles ownership on GitHub, serializes the work and requires a fresh integrated run. Release-blocking data loss, accessibility failure in a required flow, missing public lesson or failed security control stays open. Evidence-only #39/#15 workers must not quietly patch product code.
