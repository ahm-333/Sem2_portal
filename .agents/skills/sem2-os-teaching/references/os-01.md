- Slide 4 (footer 1.4): role diagram: users above system/application programs, operating system, hardware. It is an abstraction, not a syscall sequence or physical layout.
- Slide 5: hardware provides CPU/memory/I/O resources; OS controls/co-ordinates hardware use; applications use resources for users' problems; users may be people, machines or other computers. The two program labels in slide 4 are refined by slide 8.
- Slide 6: intermediary role; execute programs, convenient use, efficient hardware use. An intermediary does not itself perform every application computation.
- Slide 7: user priorities versus system view; resource allocator resolves conflicting requests; control program regulates execution to prevent errors/improper use. Efficiency/fairness are goals, not a guarantee of no errors or equal shares.
- Slide 8: no universal definition of OS; vendor bundle varies. Kernel is the continuously present core during operation; bundled system programs and applications are distinct from it. Do not identify every shipped application as kernel or turn constant availability into 100% CPU use.
